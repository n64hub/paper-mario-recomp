A fix in the shared renderer for video memory that grew as the game ran. Like v0.1.6 it contains no game data: you need your own ROM of the USA release (a big-endian `.z64` of 40 MiB, SHA-1 `3837f44cda784b466c9a2d99df70d77c322b97a0`).

> **Made with AI.** Almost all of the code was written by AI agents (Claude), directed and play-tested by a person.

**Windows:** unzip `PaperMarioRecompiled-v0.1.7-windows-x64.zip` and run `PaperMarioRecompiled.exe` from that folder (it needs a recent Visual C++ 2015-2022 redistributable, x64). **Linux (x86-64):** extract `PaperMarioRecompiled-v0.1.7-linux-x64.tar.gz` and run `PaperMarioRecompiled` in that folder (glibc 2.35 or newer, a Vulkan driver, GTK 3 and FreeType; it brings its own SDL2).

**What's new:**

- A framebuffer the game writes from the CPU, without drawing into it, no longer grows the renderer's video memory as the game runs (it grew about 20 MB a second in the game that showed it).

The [README](https://github.com/n64hub/paper-mario-recomp#readme) has what works and how to build it yourself; reports are welcome on the [issues page](https://github.com/n64hub/paper-mario-recomp/issues).
